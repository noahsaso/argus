# WebSocket cancellation and native c936 compatibility

## Repair and contract

A connection attempt previously timed out without stopping `wait-port`. When the
port eventually opened, multiple old attempts could create sockets. An older
`onopen` then sent through the shared field pointing at a newer CONNECTING socket.

The listener now owns its port probes, attempt deadline and retry delay. Cancelling
settles the waiter, destroys its probe and invalidates later continuations. A
connection generation and socket identity guard every socket callback. Subscriptions
use the captured OPEN socket, and synchronous send failures reject the attempt
with cleanup instead of escaping the event handler. Connected state is reported
only after subscriptions have been sent successfully. Disconnect also stops an
in-progress connection or backoff and allows an immediate new `connect()`. Manual
disconnection of a CONNECTING or OPEN socket emits exactly one non-reconnecting
`disconnected` event; repeated disconnects remain no-ops. Cancelling a handshake
does not emit an obsolete connection error.

`wait-port` 1.0.4 has no cancellation API, so its use in this class was replaced
with cancellable Node TCP probes. Probe timeout and polling remain one second,
with IPv4-then-IPv6 fallback for hostnames. There is no dependency or lock change.
The public constructor, event types, methods, getters, subscription JSON and
callback payloads are unchanged. RPC defaults to `http://127.0.0.1:26657`, attempt
timeout to ten seconds, and continuous reconnection to enabled. Backoff remains
1, 2, 4, 8, 16, then at most 30 seconds; an established connection loss retries
after one second. OPEN sockets still close gracefully; abandoned CONNECTING
sockets terminate. Transport error listeners remain only until transport close.

## Isolated validation

Run `npm run test:websocket`. It runs 19 deterministic lifecycle tests plus the
26 existing subscription/message/reconnection tests, without the application test
setup or database, queue, FIFO, service updater or real network connections.

The deterministic suite executes the real TypeScript with controlled clocks and
transport boundaries. It covers multiple timeout windows, late readiness, saved
stale open/close/error/message callbacks, disconnect while waiting or backing off,
immediate new connection, handshake failure/timeout, send failure, cleanup,
reentrant disconnect, DNS failure, IPv6 fallback and normal NewBlock/Tx delivery.
It also exercises the locked real `ws` implementation against an inert Duplex
stream to check asynchronous CONNECTING termination errors without TCP traffic.

Before the repair, the first nine regression cases failed. The exact c936
preimage separately fails the three core regression checks: three sockets instead
of one, the stale-open CONNECTING send exception, and an escaping send exception.
The repaired source and the unchanged listener section of the native built tracer
each pass all 19 lifecycle tests on the exact native Node binary version/hash.
Full-project TypeScript checks, tsup builds and focused ESLint checks pass.
The database-dependent application suite was not run.

## Reproducing the native fixture

Use an empty artifact directory **outside every repository/worktree**. Start in
this implementation checkout, with the native Git object available. `NODE` below
must name the qualified Node 18.17.1 executable. Do not run these commands on a
production host or copy the candidate there as part of this verification.

```sh
BASE=c9369bbfdf59dc12a70f8448e21deb7d2b779ef3
ARTIFACTS=/absolute/path/outside/repositories
FIXTURE="$ARTIFACTS/native-fixture"
IMPLEMENTATION="$PWD"
NODE=/absolute/path/to/qualified/node
mkdir -p "$FIXTURE"
git archive "$BASE" > "$ARTIFACTS/native-source.tar"
tar -xf "$ARTIFACTS/native-source.tar" -C "$FIXTURE"
git diff --binary "$BASE" -- src/services/ChainWebSocketListener.ts \
  > "$ARTIFACTS/listener.patch"
(
  cd "$FIXTURE"
  git apply --check "$ARTIFACTS/listener.patch"
  git apply "$ARTIFACTS/listener.patch"
  npm ci --legacy-peer-deps --ignore-scripts --no-audit --no-fund
  "$NODE" node_modules/patch-package/index.js
  "$NODE" node_modules/typescript/bin/tsc --noEmit
  "$NODE" node_modules/tsup/dist/cli-default.js
)
cd "$IMPLEMENTATION"
LISTENER_SOURCE="$FIXTURE/src/services/ChainWebSocketListener.ts" \
  WS_PACKAGE="$FIXTURE/node_modules/ws" \
  "$NODE" --test tests/chain-websocket-listener.cjs
LISTENER_BUNDLE="$FIXTURE/dist/scripts/tracer.js" \
  WS_PACKAGE="$FIXTURE/node_modules/ws" \
  "$NODE" --test tests/chain-websocket-listener.cjs
sha256sum "$ARTIFACTS/listener.patch" "$FIXTURE/package-lock.json" \
  "$FIXTURE/src/services/ChainWebSocketListener.ts" \
  "$FIXTURE/dist/scripts/tracer.js"
```

Independent code review and human-merge delivery remain required. Native execution
also requires its separately reviewed reconciliation plan and exact approval.
This repair does not reconstruct missing historical exports, resolve datastore
uncertainty, or authorize a deployment, service start, database write or release.
